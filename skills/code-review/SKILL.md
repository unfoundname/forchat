# 代码审查

先用 read 把目标文件完整读完（必要时 list_dir 找同目录的相关文件），然后按下面的顺序逐条检查。
**每条结论都必须带文件:行号**，没有证据的不要写，也不要把"看起来没问题"当成结论。

## 检查清单

1. **正确性**：边界条件（空、0、极长）、异常路径、空值/None、返回值类型
2. **状态与并发**：共享可变状态、重入、全局变量被意外修改
3. **资源**：文件/连接是否用 `with` 或显式关闭
4. **错误处理**：异常被吞掉、错误被当正常值、失败路径没有回执
5. **可读性**：命名、嵌套层级、超长函数
6. **安全**：路径拼接、命令/表达式注入、密钥硬编码、日志泄露

## 输出格式

标题一行结论，然后：

- **严重**（必须改）：问题 + 位置 + 为什么危险
- **建议**（可改可不改）：问题 + 位置 + 改法

末尾一句话总评（能上线 / 先修再说）。不要在结尾啰嗦地恭维代码。
